# Проверка контента

## Быстрый запуск

Из корня репозитория выполните:

```sh
dart run tool/validate_schemas.dart
dart run tool/validate_content.dart --content-set mvp
dart test packages/besprotoritsa_data/test/content_validator_test.dart
```

`tool/run_checks.sh` запускает эти проверки вместе с форматированием, строгим
анализатором и пакетными тестами. CI вызывает тот же скрипт через
`.github/workflows/ci.yml`.

## Что проверяется

Валидатор проверяет каждую запись всех JSON-наборов верхнего уровня и выбранного
набора `content/mvp/` по схеме. Для каталога и выбранного набора он также проверяет
дубли ID внутри пространств имён, i18n-ссылки, зарегистрированные effect ID и
совместимость типа эффекта с местом его применения. Для выбранного набора ссылки
на задания, локации, монстров в проверках убийства и стартовые карты разрешаются
только внутри этого набора. Для карт из items.json поле sourceDeck различает
основную колоду (`items`), колоду припасов (`supplies`) и стартовые карты с
листов персонажей (`starterItems`); `specialItems` допустим только в
special_items.json. Схема карт ограничивает статы целочисленными значениями
поддерживаемых runtime-ключей. Catalog-задания должны использовать объектные
условия с уникальными ID и положительный номер; ссылки на предметы в условиях
сбора должны вести на карту каталога, кроме шаблонных значений `item` и `supply`.
У стартового MVP-задания `chapter-1-awakening` проверяется runtime-назначение
`crew-mess`. Для каталога все сюжетные задания должны быть достижимы из
`initialQuestIds`, а граф должен содержать достижимый терминал `endsGame` с
учётом `prerequisiteQuestIds`; циклы prerequisites отклоняются. Структура
поддерживаемых ключевых слов схем проверяется до проверки записей. Для выбранного
набора проверяются структура layout, ссылки и уникальность координат/гексов,
соответствие hex ID имени runtime-файла, стартовые позиции героев/монстра,
положительное здоровье и обязательные файлы персонажей `engineer` и `guard`.
Сервер не создаёт состав больше числа персонажей, доступных в выбранном наборе.
Значения `copies` и `importBatch` должны быть положительными целыми числами;
если набор объявляет `batchSizes`, номер записи должен присутствовать в этой
таблице. `sourceDeck` сверяется с разрешёнными значениями и схемой набора.

Для `full` дополнительно сверяется инвентарь поля: одна стартовая плитка,
12 отсеков, четыре шлюза и 18 коридоров (по шесть обычных, с зелёной и красной
вентиляцией). Полный runtime-сборщик использует копии из `content/hexes.json`,
строит все 35 плиток и открывает только анабиозный отсек. Он собирает колоды
предметов, припасов, особых предметов, монстров, состояний, событий и личных
задач из каталогов с учётом `copies`; семь карт Беспокойного выделяются в
резерв смерти, каждому персонажу выдаются две личные задачи.

Офлайн-мастер новой игры поддерживает выбор `mvp` или `full`. Серверный
`TrustedContentRepository` пока принимает только `mvp`; это ограничение не
меняет локальный runtime-путь. В `mvp` состав и порядок карт остаются
фиксированными по `content/mvp`. Ошибка указывает файл и ID записи (или явный
маркер набора/документа, если ID отсутствует).

Английские переводы проверяются для карточек со статусом
`human-card-verified`; остальные записи каталога пока проверяются по русской
локали. Редакторская проверка иллюстраций остаётся ручной. Успешный валидатор не меняет
`content/review_status.json` и не выставляет статус визуальной сверки. Для
проверки макета откройте оригиналы в `materials/`; числовые значения, значки,
копии и характеристики не считаются проверенными машинной валидацией.

## Отрицательные фикстуры

`packages/besprotoritsa_data/test/fixtures/content-audit/` содержит независимые
поломки ссылок на задания/локации/монстров/предметы, дубликата начального
задания и условия внутри задания, строкового условия catalog-задания,
отсутствующего номера задания и недостижимой боковой ветви,
терминального исхода и prerequisites, i18n, схемы,
`importBatch`, `sourceDeck`, `copies`, регистрации effect ID и типа hook,
enum-значения, уникальности ID, стартовой карты, доступности внутри выбранного
набора, отсутствующего sourceDeck, недопустимого источника колоды, нескольких
неверных keyword-значений схемы, нулевой цели задачи, дробного/неизвестного стата,
несовпадающего event hook, неправильного адреса стартового MVP-задания и ошибок
layout. Тесты
`content_validator_test.dart` и
`trusted_content_repository_test.dart` проверяют, что каждая такая ошибка
отклоняется и сообщение содержит ID записи и путь.

## Основание

На момент усиления валидаторов ожидаемый `docs/content-audit.md` в рабочем дереве
отсутствовал. Проверки собраны по существующим `content/schemas/`, данным,
`docs/effects-vocabulary.md`, существующим тестам целостности и явно перечисленным
требованиям этой задачи. Отсутствие отчёта контент-аудита не трактуется как
подтверждение полноты или визуальной точности карточек.
