# Проверка контента

## Быстрый запуск

Из корня репозитория выполните:

```sh
dart run tool/validate_schemas.dart
dart run tool/validate_content.dart --content-set mvp
dart test packages/besprotoritsa_data/test/content_validator_test.dart
```

`tool/run_checks.sh` запускает эти проверки вместе с форматированием, строгим
анализатором и пакетными тестами. CI вызывает тот же скрипт через
`.github/workflows/ci.yml`.

## Что проверяется

Валидатор проверяет каждую запись всех JSON-наборов верхнего уровня и выбранного
набора `content/mvp/` по схеме. Для каталога и выбранного набора он также проверяет
дубли ID внутри пространств имён, i18n-ссылки, зарегистрированные effect ID и
совместимость типа эффекта с местом его применения. Для выбранного набора ссылки
на задания, локации и стартовые карты разрешаются только внутри этого набора.
Граф сюжетных заданий каталога должен содержать достижимый терминал `endsGame` с
учётом `prerequisiteQuestIds`; циклы prerequisites отклоняются. Для выбранного
набора проверяются структура layout, ссылки и уникальность координат/гексов,
обязательные файлы персонажей `engineer` и `guard`. Сервер не создаёт состав
больше числа персонажей, доступных в выбранном наборе.
Значения `copies` и `importBatch` должны быть положительными целыми числами;
если набор объявляет `batchSizes`, номер записи должен присутствовать в этой
таблице. `sourceDeck` сверяется с разрешёнными значениями и схемой набора.

Сейчас поддерживаемый runtime `contentSetId` — `mvp`, как и в
`TrustedContentRepository`. Каталожные JSON проверяются на структуру и связи
кампании, но не подмешиваются в runtime-набор. Ошибка указывает файл и ID записи
(или явный маркер набора/документа, если ID отсутствует).

Редакторская проверка иллюстраций остаётся ручной. Успешный валидатор не меняет
`content/review_status.json` и не выставляет статус визуальной сверки. Для
проверки макета откройте оригиналы в `materials/`; числовые значения, значки,
копии и характеристики не считаются проверенными машинной валидацией.

## Отрицательные фикстуры

`packages/besprotoritsa_data/test/fixtures/content-audit/` содержит независимые
поломки ссылок на задания/локации, терминального исхода и prerequisites, i18n, схемы,
`importBatch`, `sourceDeck`, `copies`, регистрации effect ID и типа hook,
enum-значения, уникальности ID, стартовой карты, доступности внутри выбранного
набора и ошибок layout. Тесты `content_validator_test.dart` и
`trusted_content_repository_test.dart` проверяют, что каждая такая ошибка
отклоняется и сообщение содержит ID записи и путь.

## Основание

На момент усиления валидаторов ожидаемый `docs/content-audit.md` в рабочем дереве
отсутствовал. Проверки собраны по существующим `content/schemas/`, данным,
`docs/effects-vocabulary.md`, существующим тестам целостности и явно перечисленным
требованиям этой задачи. Отсутствие отчёта контент-аудита не трактуется как
подтверждение полноты или визуальной точности карточек.
