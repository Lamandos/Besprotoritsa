# Словарь предметной области

Этот словарь является нормативным мостом между текстом настольных правил,
моделью состояния и подписями интерфейса. В коде используются ровно имена из
колонки «Термин кода»; экран может локализовать их, но не вводит второе значение
термина. Если буклет и этот документ расходятся, для цифровой реализации
приоритет имеют этот словарь и `docs/rules-spec.md`.

| Термин правил настолки | Термин кода | Термин экранного интерфейса | Норма |
| --- | --- | --- | --- |
| сектор, фрагмент поля | `HexTile` | сектор | Базовая клетка модульного поля. Слово «сектор» не означает регион из нескольких клеток. |
| отсек | `Compartment` | отсек | Разновидность `HexTile`; может содержать терминал. |
| коридор | `Corridor` | коридор | Разновидность `HexTile`, соединяющая отсеки. Закрытый коридор непроходим. |
| стартовая зона, анабиозный отсек | `HexTile(type: start)` | анабиозный отсек | Стартовый отсек, где расположен общий сундук. |
| шлюз | `AirlockPort` | шлюз | Особый порт быстрого перехода между шлюзами; это не отдельный тип обычного коридора. |
| вентиляция; зелёная/красная вентиляция | `VentColor` | вентиляция | Свойство клетки или вентиляционного порта. Значение — цвет (`green` или `red`), а не произвольная строка интерфейса. |
| грань, выход, стык | `HexEdge` | выход | Одна из шести направленных граней клетки, `HexEdge(0..5)`. |
| припас | `SupplyCard` | припас | Вспомогательная или расходная карта из колоды припасов; может покупаться, продаваться и быть наградой. |
| предмет | `ItemCard` | предмет | Карта экипировки из обычной колоды предметов: оружие, одежда, броня, робот или модификация. |
| особый предмет | `SpecialItemCard` | особый предмет | Карта экипировки из отдельной колоды; не является экземпляром `SupplyCard`. |
| модификация; «имплант» в разговорной речи | `Modification` | модификация | В коде запрещено имя `Implant`/`implant`: модификация сначала переносится в `carriedMods`, затем может быть необратимо вживлена в `implanted`. |
| невживлённая модификация | `carriedMods` | модификации при себе | Отдельная неограниченная зона модификаций. Она не занимает ни слот рюкзака, ни слот экипировки. |
| вживлённая модификация | `implanted` | вживлённые модификации | Зона максимум на две `Modification`; переход из `carriedMods` необратим. |
| рюкзак | `backpack` | рюкзак | Зона максимум на три неэкипированных предмета или припаса; модификации в неё не входят. |
| состояние, рана | `ConditionCard` | состояние | Карта последствия ранения. «Рана» в правилах — факт получения хотя бы одного урона от атаки, а не отдельный тип сущности. |
| Нарыв | `BoilToken` | Нарыв | Неподвижный жетон угрозы, а не карта монстра. Его совмещение с игроком обрабатывает `resolveColocation`. |
| Беспокойный | `RestlessMonster` | Беспокойный | Особый монстр, возникающий при смерти персонажа и несущий допустимое снаряжение погибшего. |
| монстр | `MonsterState` | монстр | Экземпляр монстра на поле; его карта определяет параметры и особенность. |
| колода монстров | `MonsterDeck` | колода монстров | Источник обычных монстров. Карты Беспокойных резервируются при подготовке и не тянутся из неё. |
| событие, карта события | `EventCard` / `EventDeck` | событие / колода событий | Единственное каноническое название колоды событий. |
| «карта встречи» в правиле смерти | `EventCard` | карта события | Это редакторская неточность оригинала: при смерти постоянная «карта встречи» трактуется как постоянная `EventCard` и уходит в сброс колоды событий. Отдельной колоды встреч не существует. |
| сюжетное задание | `StoryQuestCard` / `StoryQuestDeck` | сюжетное задание | Нумерованная цепочка, выполнение которой ведёт к победе. |
| личная задача | `PersonalTaskCard` / `PersonalTaskDeck` | личная задача | Закрытая непередаваемая задача игрока. |
| кредиты | `Credits` | кредиты | Валюта в жетонах; не является картой и не хранится в сундуке. |
| урон | `Damage` | урон | Число потерянных очков здоровья; экран показывает его жетонами/счётчиком. |
| защита, броня | `armor` | броня | Параметр снижения урона. Момент его применения определён в спецификации правил. |

## Правила именования

- Типы, поля состояния и идентификаторы эффектов используют английские имена из
  второй колонки. Русские термины остаются только в локализации и документации.
- `HexTile` — общий тип клетки. `Compartment` и `Corridor` не являются синонимами
  `HexTile`, а являются его специализациями.
- Названия собственных сущностей в UI пишутся с заглавной буквы: «Нарыв»,
  «Беспокойный». Типы карт в обычном тексте пишутся со строчной: «припас»,
  «состояние».
