# BUG-2026-055 — Растяжка не срабатывает на монстра из обычного события

## Суть

Обычный эффект события `spawn_monster` добавляет монстра прямо в клетку героя,
но не вызывает обработку прибытия. Растяжка в этой клетке не уничтожает
появившегося монстра.

## Среда

- Версия приложения / commit: PR #33, commit `f45a6f2`.
- Платформа и версия ОС / браузера: rules package.
- Устройство или размер окна, если важно: не важно.
- Режим игры / состав партии / seed, если важно: событие с эффектом `spawn_monster`; растяжка в клетке героя.

## Подготовка и шаги воспроизведения

1. Разместить растяжку в клетке героя.
2. Разыграть событие, исход которого выполняет `spawn_monster`.
3. Проверить появившегося монстра.

Частота воспроизведения: всегда.

## Результат

- **Фактический:** монстр остаётся на поле и проходит обычную обработку появления/атаки.
- **Ожидаемый:** растяжка срабатывает на не-босса, появившегося в её секторе, уничтожает его и отправляется в сброс.
- **Основание ожидания:** текст карты растяжки в `content/i18n/ru.json`: убийство врага, «появившегося или зашедшего» в сектор; `docs/effects-vocabulary.md` (`monster.trapOnEnter`).

## Влияние

- Игрок не получает предусмотренную защиту от появления монстра в заминированном секторе.
- Масштаб / обходной путь: работает только для других путей появления, проходящих через общий обработчик.

## Доказательства

Новое замечание ревью PR #33: `discussion_r4235392485`.

- Подозреваемая область кода: ветка `spawn_monster` в `_resolveEventOutcome`.
- Релевантные существующие тесты / спецификации: `BUG032 a deployed tripwire kills the next non-boss entrant`; `BUG048 asteroid relocation triggers a tripwire on the arrival tile`.
- Что пока неизвестно: нет.

## Регрессионный тест

- Тестовый файл и имя теста: `packages/besprotoritsa_rules/test/mvp_round_loop_test.dart` — `BUG055 event monster spawn triggers a tripwire`.
- Команда запуска: `cd packages/besprotoritsa_rules && dart test test/mvp_round_loop_test.dart --name 'BUG055'`.
- **До исправления (красный):** `cd packages/besprotoritsa_rules && dart test test/mvp_round_loop_test.dart --name 'BUG055'` — завершился провалом assertion.
- Результат и причина падения: ожидалось отсутствие монстра и срабатывание растяжки, фактически в состоянии остался `MonsterInstance`; ветка обычного `spawn_monster` не вызывала обработку прибытия.
- **После исправления (зелёный):** `cd packages/besprotoritsa_rules && dart test test/mvp_round_loop_test.dart --name 'BUG055'` — тест прошёл; появившийся монстр уничтожен растяжкой и карта отправлена в сброс.
- Результат связанных проверок: `BUG055` и существующие тесты появления/перемещения монстров прошли.

## Исправление

- Изменённые файлы: `packages/besprotoritsa_rules/lib/src/commands_reducer_part_7.dart`; `packages/besprotoritsa_rules/test/mvp_round_loop_test.dart`.
- Краткое описание исправления: обычный `spawn_monster` сначала вызывает обработчик прибытия растяжки; непосредственная атака запускается только для выжившего монстра.
- Остаточные ограничения или связанные баги: другие специальные ветви появления проверяются отдельными тестами.
