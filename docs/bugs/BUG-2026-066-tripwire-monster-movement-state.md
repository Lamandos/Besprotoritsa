# BUG-2026-066 — Убийство монстра растяжкой переносит его шаги на следующего

## Суть

Если растяжка убивает монстра до завершения его движения, остаток его
`monsterStepsRemaining` используется следующим монстром вместо полного лимита
движения следующего монстра.

## Среда

- Версия приложения / commit: PR #33, commit `e6f38ba`.
- Платформа и версия ОС / браузера: rules-пакет.
- Устройство или размер окна, если важно: не важно.
- Режим игры / состав партии / seed, если важно: фаза монстров; первый монстр погибает на растяжке во время движения.

## Подготовка и шаги воспроизведения

1. Разместить растяжку на открытом пути монстров.
2. Поставить первым в очереди монстра с несколькими очками движения, который погибнет при входе на растяжку.
3. Следующим поставить монстра с несколькими очками движения и завершить ход игроков.

Частота воспроизведения: всегда.

## Результат

- **Фактический:** следующий монстр получает лишь число шагов, оставшееся у погибшего монстра.
- **Ожидаемый:** после удаления текущего монстра очередь остаётся на следующем монстре, но его движение начинается с полного собственного лимита.
- **Основание ожидания:** `docs/rules-spec.md`, раздел «Структура раунда», задаёт детерминированную очередь, в которой каждый монстр выполняет своё движение; `MonsterInstance.movement` задаёт число секторов, проходимых этим монстром за раунд.

## Влияние

- Монстры после жертвы растяжки перемещаются меньше положенного; результат фазы зависит от того, погиб ли предыдущий монстр.
- Масштаб / обходной путь: растяжка убивает монстра с несколькими очками движения.
