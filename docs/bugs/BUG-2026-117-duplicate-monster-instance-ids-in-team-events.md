# BUG-2026-117 — Командное событие создаёт монстров с одинаковыми ID

## Суть

Если два героя выбирают в командном событии один и тот же вариант появления монстра,
а из колоды вытягиваются карты одного типа, создаваемые экземпляры получают один
`instanceId`. Последующие операции по ID могут обратиться к первому монстру вместо
нужного.

## Среда

- Версия приложения / commit: PR #38, ветка `codex/team-event-choices`.
- Платформа и версия ОС / браузера: движок правил; не зависит от платформы.
- Устройство или размер окна, если важно: не применимо.
- Режим игры / состав партии / seed, если важно: командное событие с двумя живыми
  героями и двумя картами одного типа в колоде монстров.

## Подготовка и шаги воспроизведения

1. Создать командное событие, вариант которого порождает монстра без немедленного боя.
2. Положить в колоду две карты монстра с одним и тем же ID типа.
3. Оба героя выбирают этот вариант и подтверждают выборы.
4. Сравнить `instanceId` появившихся монстров.

Частота воспроизведения: всегда при совпадении типа вытянутых монстров.

## Результат

- **Фактический:** оба экземпляра получают одинаковый `instanceId`, образованный из
  раунда, индекса события, ID события, варианта и ID типа монстра.
- **Ожидаемый:** каждый отдельный экземпляр монстра имеет уникальный `instanceId`,
  чтобы немедленный бой и последующие эффекты адресовали именно этот экземпляр.
- **Основание ожидания:** замечание к PR #38; модель и правила операций с монстрами
  адресуют конкретные экземпляры по `instanceId`, а события разрешаются
  последовательно согласно `docs/rules-spec.md`, § «Фаза событий».

## Влияние

- Что пользователь не может сделать или какое состояние портится: бой, ловушки и
  последующие операции по ID могут изменять не того монстра.
- Масштаб / обходной путь: командные события с несколькими одинаковыми появлениями
  одного типа монстра; надёжного обходного пути нет.
