# Правила кода «Беспроторица»

## Лимиты по пакетам

| Пакет | Строк в файле | Строк в методе | Вложенность блоков |
| --- | ---: | ---: | ---: |
| `besprotoritsa_rules` | 300 | 40 | 3 |
| `besprotoritsa_data` | 400 | 50 | 3 |
| `besprotoritsa_app` | 500 | 80 | 5 |

Предел для метода в `besprotoritsa_app` применяется в том числе к `build()`.
При превышении лимита код следует разделить на небольшие именованные части.

## Границы пакетов

- `besprotoritsa_rules` — чистое детерминированное Dart-ядро. Импорты `flutter`,
  `flutter_*` и любые зависимости от Flutter в нём запрещены.
- `besprotoritsa_data` отвечает за схемы, валидаторы и загрузку контента; UI-логика
  в нём не размещается.
- `besprotoritsa_app` — единственный пакет, содержащий Flutter UI.

## Dart 3 и Flutter

- В одном файле допускается семейство `sealed class` и связанных с ним классов ADT.
  Это исключение из лимита строк файла для моделей команд, событий и состояний.
- Анализ выполняется через `very_good_analysis` в строгом режиме: `strict-casts`,
  `strict-inference` и `strict-raw-types` включены. `dart_code_metrics` запрещён.
- Конструкторы виджетов объявляются `const`, где это возможно.
- Тяжёлые статичные фрагменты интерфейса, включая игровое поле и фон отсеков,
  изолируются `RepaintBoundary`.
